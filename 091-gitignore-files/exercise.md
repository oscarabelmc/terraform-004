# Terraform GitIgnore Exercise

**Domain:** Security
**Topic:** Terraform files to ignore in Git

## Description

Which of the following Terraform files should be ignored by Git when committing code to a repo

## Learning Objectives

- Files that should be ignored
- Files that SHOULD be committed
- Standard Terraform .gitignore
- What happens if you commit state

## Background

Terraform generates several files that should **not** be committed to version control. Some contain sensitive data, others are machine-specific caches. A proper `.gitignore` prevents accidental commits of these files.

## Steps

### Part 1 — Files that should be ignored

1. **`terraform.tfstate` and `terraform.tfstate.backup`:**

   State files contain **all resource attributes in plain text** — including passwords, access keys, and other sensitive data. They also change with every apply, causing noisy diffs.

   ```json
   {
     "resources": [{
       "type": "random_password",
       "instances": [{
         "attributes": {
           "result": "super-secret-password"  ← Plain text secrets!
         }
       }]
     }]
   }
   ```

   ❌ **Never commit state files to Git.**

2. **`.terraform/` directory:**

   Contains provider plugins, module cache, and backend configuration. All platform-specific and regenerated by `terraform init`.

   ❌ **Never commit the `.terraform/` directory.**

3. **`*.tfvars` files with secrets:**

   While `terraform.tfvars` or `*.auto.tfvars` can be committed if they contain only non-sensitive defaults, files with secrets (passwords, keys) should be in `.gitignore`.

4. **`crash.log`:**

   Generated when Terraform crashes. Contains debug information.

5. **`override.tf` / `override.tf.json`:**

   Occasionally used for local overrides — not intended for shared repos.

### Part 2 — Files that SHOULD be committed

6. **Files to keep in version control:**

   | File | Reason |
   |------|--------|
   | `*.tf` (main.tf, variables.tf, outputs.tf) | Core config — must be versioned |
   | `*.tf.json` | JSON-format config |
   | `*.tfvars` (non-sensitive defaults) | Variable defaults can be shared |
   | `*.hcl` | Sentinel policies, packer configs |
   | `terraform.lock.hcl` | Provider version locks — commit this! |
   | `modules/` (local module code) | Module source code |

### Part 3 — Standard Terraform .gitignore

7. **Recommended .gitignore:**

   ```gitignore
   # Local .terraform directories
   **/.terraform/*

   # .tfstate files
   *.tfstate
   *.tfstate.*

   # Crash log files
   crash.log
   crash.*.log

   # Exclude all .tfvars files, which are likely to contain secrets
   *.tfvars
   *.tfvars.json

   # Ignore override files
   override.tf
   override.tf.json
   *_override.tf
   *_override.tf.json

   # Include tfplan files but mention their risk
   *.tfplan
   ```

### Part 4 — What happens if you commit state

8. **Risks of committing state to Git:**

   - **Secret exposure** — passwords, keys, connection strings in plain text in Git history
   - **Commit history permanently stores secrets** — even if you remove the file later, secrets remain in old commits
   - **Conflicts** — state changes on every apply, causing merge conflicts
   - **No locking** — Git doesn't provide state locking
