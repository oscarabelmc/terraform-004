## Why B Is Correct

`terraform.tfstate` should be ignored by Git because:

| Reason | Detail |
|--------|--------|
| **Sensitive data** | Contains all resource attributes in plain text (passwords, keys, IPs) |
| **Noisy diffs** | Changes on every apply — pollutes commit history |
| **Merge conflicts** | Binary-like JSON diffs cause frequent conflicts |
| **No locking** | Git doesn't provide the locking Terraform needs |
| **Permanent exposure** | Secrets committed once live in Git history forever |

### What makes state different from config files

```
Version Control (Git)            State (terraform.tfstate)
┌──────────────────────┐        ┌──────────────────────────┐
│ main.tf             │        │ Resource IDs             │
│ variables.tf        │        │ Real-world attributes    │
│ outputs.tf          │        │ Sensitive data (secrets) │
│ terraform.lock.hcl  │        │ Dependency metadata      │
│                      │        │                          │
│ ✅ Commit these     │        │ ❌ Do NOT commit        │
└──────────────────────┘        └──────────────────────────┘
```

## Best Practices

| File | In VCS? | Notes |
|------|---------|-------|
| `*.tf` | ✅ Yes | All configuration files |
| `terraform.tfstate` | ❌ No | Use remote backend |
| `.terraform/` | ❌ No | Regenerated by `init` |
| `terraform.lock.hcl` | ✅ Yes | Provider version lock |
| `*.tfvars` (non-sensitive) | ✅ Yes | Shared variable values |
| `*.tfvars` (with secrets) | ❌ No | Use HCP variable sets or CI/CD env vars |
| `crash.log` | ❌ No | Debug output |
