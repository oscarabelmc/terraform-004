# Resource Reference Exercise

**Exam Question:** You're deploying AWS infrastructure and writing the configuration as shown below. What does the reference `aws_vpc.main.id` in the subnet configuration accomplish?

```hcl
resource "aws_vpc" "main" {
  cidr_block = "10.5.0.0/16"

  tags = {
    Name = "production-vpc"
  }
}

resource "aws_subnet" "public" {
  vpc_id     = aws_vpc.main.id
  cidr_block = "10.5.2.0/24"

  tags = {
    Name = "bk-public-subnet"
  }
}
```

## Background

Terraform uses **attribute references** (`resource_type.name.attribute`) to pass values between resources. Every attribute reference serves two purposes simultaneously:

1. **Value retrieval** — gets the attribute value from the referenced resource
2. **Implicit dependency** — tells Terraform the referenced resource must exist first

## Steps

### Part 1 — Examine the reference

1. **Open `main.tf`:**

   ```bash
   cat main.tf
   ```

   The subnet's `vpc_id` is set to `aws_vpc.main.id` — a reference to the VPC resource's `id` attribute.

### Part 2 — Understand what the reference provides

2. **Value retrieval:**

   The `aws_vpc.main.id` reference gets the **actual VPC ID** that AWS assigns when the VPC is created. This ID is not known until `terraform apply` runs — it's a **computed attribute** generated by the AWS API.

   ```hcl
   vpc_id = aws_vpc.main.id
   # At runtime, this resolves to something like "vpc-0a1b2c3d4e5f67890"
   ```

3. **Implicit dependency:**

   Because the subnet references `aws_vpc.main.id`, Terraform knows it must create the VPC **before** the subnet. This is an implicit dependency — no `depends_on` needed.

### Part 3 — Verify the dependency

4. **Initialize and generate a plan:**

   ```bash
   terraform init
   terraform plan
   ```

   The plan shows the VPC created first, then the subnet. Terraform's dependency graph enforces this ordering.

5. **Generate the graph:**

   ```bash
   terraform graph | dot -Tsvg > graph.svg
   ```

   The graph shows:
   ```
   aws_vpc.main ──→ aws_subnet.public
   ```

### Part 4 — What happens if you remove the reference?

6. **Edit `main.tf`** and replace the reference with a hardcoded string:

   ```hcl
   vpc_id = "vpc-12345"
   ```

7. **Re-plan:**

   ```bash
   terraform plan
   ```

   The implicit dependency is gone. Terraform may attempt to create the VPC and subnet **in parallel**, or the subnet first — which would fail because the VPC doesn't exist yet. The reference both retrieves the value **and** orders the resources.

- C. It only creates an explicit dependency via `depends_on`
