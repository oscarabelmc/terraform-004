# Terraform Apply Exercise

**Exam Question:** What happens when a `terraform apply` command is executed?

## Background

`terraform apply` is the third step in the core Terraform workflow (Write → Plan → **Apply**). It takes the execution plan generated by `terraform plan` and **executes it** — making the real infrastructure match the desired configuration.

## Steps

### Part 1 — Understand what apply does

1. **The apply process:**

   ```
   terraform apply
        │
        ├── 1. Generate plan (if no plan file provided)
        │      └── Shows what will change
        │
        ├── 2. Prompt for confirmation (default behavior)
        │      └── "Do you want to perform these actions?"
        │
        ├── 3. Execute the plan
        │      ├── Create resources (+)
        │      ├── Update resources (~)
        │      ├── Destroy resources (-)
        │      └── Replace resources (-/+)
        │
        ├── 4. Update state file
        │      └── Write new resource IDs, attributes, metadata
        │
        └── 5. Display outputs
               └── Show output values from outputs.tf
   ```

### Part 2 — Apply with and without a plan file

2. **Without a plan file (default):**

   ```bash
   terraform apply
   ```

   - Terraform runs `plan` internally
   - Shows you the plan
   - **Prompts for confirmation** (type `yes`)
   - Executes the changes

3. **With a saved plan file:**

   ```bash
   terraform plan -out=plan.tfplan
   terraform apply plan.tfplan
   ```

   - Uses the exact reviewed plan
   - **No confirmation prompt** (already approved)
   - Guarantees the exact reviewed changes are applied

### Part 3 — Apply behavior

4. **Key behaviors of apply:**

   | Behavior | Detail |
   |----------|--------|
   **Confirmation** | Prompts for `yes` by default (unless `-auto-approve`) |
   **State update** | Writes final state after successful apply |
   **Parallelism** | Applies independent resources in parallel (default 10) |
   **Error handling** | Stops on error; resources created before error remain |
   **Idempotency** | Safe to re-run — only changes what's needed |

5. **Auto-approve (for CI/CD):**

   ```bash
   terraform apply -auto-approve
   ```

   Skips the confirmation prompt. Use in automation only.

### Part 4 — What apply does NOT do

6. **Apply does NOT:**

   - Validate syntax (that's `validate`)
   - Check formatting (that's `fmt`)
   - Import resources (that's `import`)
   - Destroy everything (that's `destroy`, which is apply with empty config)
